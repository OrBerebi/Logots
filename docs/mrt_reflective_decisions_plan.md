# Implementation: `mrt_reflective_decisions`

---

## 1. Context

Products like Petcube and Furbo already do a decent job at remote monitoring and basic laser/treat interaction. What they all share is a fundamental limitation: they are **reactive**. They respond to a trigger and execute a fixed response. There is no memory of what happened 30 seconds ago, no understanding of a pattern building over time, and no judgment about whether the current response is actually the right one.

Our architecture already goes further than this — we have a multi-modal experience layer (`mrt_experience`) that fuses vision, audio, and motion into a continuous, timestamped picture of what the robot is perceiving. The reactive rule engine (`decision_engine.py`) reads from this and fires well-defined responses. That layer is solid and we keep it.

`mrt_reflective_decisions` is the layer **above** the rules — it reads the same experience data but asks a different question: not *"what is happening right now?"* but *"what should we do about the situation we've been in for the last minute?"* An LLM sits on top of our pipeline, reviews recent experience every 20 seconds, and injects strategic decisions that the rule engine alone would never make.

---

## 2. Data Flow

```
mrt_experience_data (buffer.master_mrt)
        │
        ├──► decision_engine.py                ← reactive rules, every ~3s (per chunk)
        │         └──► mrt_immediate_decisions
        │                   └──► mrt_decisions_to_actions ──► BRAIN_COMMAND_QUEUE
        │
        └──► mrt_reflective_decisions.py       ← LLM strategic layer, every ~20s
                  ├──► mrt_decisions_to_actions ──► BRAIN_COMMAND_QUEUE
                  └──► mrt_reflective_log.jsonl (reasoning trace)
```

Voice commands flow through the reactive path: Whisper transcription is embedded in every `mrt_experience` row as `voice_transcription`, and `rule_voice_command` in the decision engine does keyword matching ("back off", "get closer", "play arm") on each chunk. The reflective layer adds **semantic** voice understanding on top — it reads the same transcription text from the experience window and can interpret natural language commands the keyword matcher would miss (e.g. *"Can you come closer?"*, *"Leave her alone"*).

### Inputs

| Input | Source | Why |
|---|---|---|
| `buffer.master_mrt` (tail 250 for voice, tail 40 for experience summary) | `ThreadSafeBuffer` | Wide window (~60s) ensures voice commands aren't missed between 20s cycles; narrow window keeps prompt tokens low |
| `buffer.master_decisions` (tail 10) | `ThreadSafeBuffer` | What the rule engine has been deciding — prevents redundant actions |
| `BRAIN_COMMAND_QUEUE.qsize()` | `recording_module.py` | Queue depth — skips the cycle if the robot is already mid-action (>10 pending) |

### Output

A single action row in the `mrt_decisions_to_actions` schema, injected into `BRAIN_COMMAND_QUEUE`:

```python
{
    'decision_id': 1,
    'timestamp': datetime.now(),
    'source_module': 'mrt_reflective_decisions',
    'source_event_id': 'ref_<8-char uuid hex>',
    'experience_id': <last experience_id in window>,
    'decision_type': 'get_closer' | 'back_off' | 'play_arm',
    'parameters': '<json str from d_engine.get_action_parameters()>'
}
```

Action parameters are generated by the same `d_engine.get_action_parameters()` and `e_engine.build_mrt_motor()` that the reactive pipeline uses. Motor commands are downsampled from 10Hz to 4Hz (matching `FPS`) before being queued.

## 3. Operating Mode

### Thread Architecture

`mrt_reflective_decisions` runs as a dedicated daemon thread (`t_reflect`), started alongside the other threads in `run_data_collection()`. It runs on a 20-second timer, independently of the chunk pipeline.

It does **not** run inside `process_chunk()`. The LLM call takes 0.5–2 seconds, which would stall the 4fps pipeline. It lives on its own thread and reads from the shared `ThreadSafeBuffer` under a brief lock without blocking anything.

Circular imports are avoided via lazy imports: `from .recording_module import BRAIN_COMMAND_QUEUE` is called inside `reflective_decision_loop()` and `inject_reflective_decision()`, not at module level.

### Frequency: Every 20 Seconds (Adaptive)

- The reactive rule engine fires every ~3 seconds (12 frames @ 4fps) — it handles real-time reflexes.
- The reflective layer looks at patterns. 20 seconds of experience gives ~80 frames, ~6 rule-engine cycles, and a meaningful behavioral window.
- An API call every 20 seconds costs roughly $0.002–0.01 per call with Claude Haiku — negligible for hours of operation.

**Adaptive suppression**: If `BRAIN_COMMAND_QUEUE` already has more than 10 items pending, the reflective layer skips its cycle. It doesn't interrupt a sequence already in motion.

The sleep uses 0.1s increments (`interval * 10` iterations) so that `stop_event` is checked frequently and the thread exits promptly when recording stops.

### LLM: Claude Haiku via Anthropic API

**Model: `claude-haiku-4-5-20251001`**

- **Latency**: ~0.5–2s response time, fits comfortably in a 20-second cycle
- **Cost**: ~10x cheaper than Sonnet, runs indefinitely without meaningful expense
- **Capability**: Reading a compressed context block and returning a JSON decision is well within Haiku's abilities — classification + judgment, not deep reasoning
- **Future path**: if we move to a Jetson Orin NX, the API call can be swapped for a local model and the architecture stays identical

The prompt uses **structured JSON output** — the system prompt instructs the model to respond only with a JSON object. The parser strips markdown fences (```` ```json ... ``` ````) if the model wraps the output.

## 4. Core Functions

### `format_experience_context(mrt_df, n_rows=40) → str`

Compresses the last 40 rows of experience into ~4 summary blocks using pandas `groupby` (not `np.array_split`, which triggers a deprecated `swapaxes` warning). Each block summarizes:

- Time range (relative seconds from oldest row)
- Cat detection rate (e.g. `cat_detected=3/10`)
- Average cat position X (when detected)
- Distance trend (mode of `cat_distance_change`)
- Meow count and max loudness
- Mean movement intensity

Voice transcriptions are appended separately, deduplicated by text content:

```
[t=0–3s] cat_detected=8/10, avg_cat_x=287, distance_trend=closer, movement_intensity=0.42
[t=3–6s] cat_detected=10/10, avg_cat_x=310, distance_trend=no_change, meows=2 (max_loudness=medium), movement_intensity=0.18
[t=6–9s] cat_detected=5/10, distance_trend=farther, movement_intensity=0.05
[t=9–12s] cat_detected=0/10, movement_intensity=0.00

Voice transcriptions:
  [t=5s] "Can you come closer?"
```

---

### `format_decision_history(decisions_df, n_rows=10) → str`

Summarizes recent rule engine decisions by count and time span:

```
Recent rule engine decisions:
- center_gaze x6
- get_closer x1
(over last 18s)
Not attempted: back_off, play_arm
```

---

### `build_reflective_prompt(experience_context, decision_history, voice_text=None) → dict`

Returns a dict with `"system"` (str) and `"messages"` (list of dicts) for the Anthropic SDK.

**System prompt** (fixed):

```
You are the strategic brain of a cat-sitter robot named Logots. Every 20 seconds
you review the robot's recent sensory experience and decide whether to take a
high-level action.

Available actions:
- "get_closer": Approach the cat. Use when cat is stationary, calm, and not stressed.
- "back_off": Retreat to create distance. Use when cat seems agitated, scared, or movement intensity is high.
- "play_arm": Wave the robot's arm playfully. Use when cat is nearby, engaged, and seems relaxed.
- "no_action": Do nothing — let the reactive rule system handle it. This is the default and preferred choice when the situation is already being handled.

Rules:
- Prefer "no_action" unless you see a clear opportunity the reactive rules are missing.
- Never override a safety stop (high movement_intensity).
- If a voice command from the user is present, prioritize it over sensor-based reasoning.
- Do not repeat an action the rule engine is already executing frequently.

Respond ONLY with a JSON object:
{"decision": "<action>", "reasoning": "<1-2 sentence explanation>"}
```

**User message** (dynamic):

```
## Recent Experience
<experience_context>

## Rule Engine Decisions
<decision_history>

## Voice Command          ← only if voice_text is present
User said: "<voice_text>"

What should the robot do?
```

---

### `call_llm(prompt_bundle, model, timeout=8.0) → dict | None`

Wraps the Anthropic Python SDK call. `anthropic` is imported lazily inside the function so the module can be loaded even if the SDK is not installed. The API key is read from `ANTHROPIC_API_KEY` env var.

The response text is stripped of markdown fences if present, then parsed as JSON. **Never raises** — all exceptions are caught, logged, and return `None`. A failed LLM call means the reflective layer silently skips this cycle.

---

### `parse_and_validate_response(raw_response) → dict | None`

Validates that `decision` is one of `{'get_closer', 'back_off', 'play_arm', 'no_action'}`. Falls back to `no_action` if the response is malformed or unrecognized. This is the safety gate — the LLM cannot hallucinate an unknown action into the motor cortex.

---

### `inject_reflective_decision(buffer, decision_type, reasoning, experience_id) → None`

1. Reads the last row of `buffer.master_mrt` (under lock) for current sensor context (e.g. `cat_position_x` for visual servoing)
2. Calls `d_engine.get_action_parameters(decision_type, last_row)` — same definitions used by the reactive pipeline
3. Builds an action row in `mrt_decisions_to_actions` schema with `source_module='mrt_reflective_decisions'`
4. Generates motor commands via `e_engine.build_mrt_motor()` (start_frame_id=900,000 to avoid collisions with chunk-based IDs)
5. Appends to `buffer.master_actions` and `buffer.master_gen_motor` (under lock)
6. Downsamples motor frames from 10Hz to 4Hz and puts commands into `BRAIN_COMMAND_QUEUE`

## 5. Key Design Decisions

### No New Buffer Attributes

Voice transcription is already embedded in `buffer.master_mrt` as the `voice_transcription` column (populated by `audio_transcription_producer` → `build_mrt_experiences`). The reflective layer reads it directly from the experience snapshot. No `buffer.last_voice_text` or other new attributes were needed.

### Wide Window for Voice, Narrow for Experience

At 4fps, the 40-row experience window covers only ~10 seconds. Voice commands spoken 15 seconds before a reflective cycle would be missed. The fix: snapshot 250 rows (~60s) for voice text extraction, but compress only the last 40 rows into the LLM prompt for token efficiency.

### Voice Text Deduplication by Content

The `transcription_seq_id` column is not always populated (depends on timing between the Whisper producer and the experience builder). Deduplication uses the text content directly (`drop_duplicates(subset='text_str')`) rather than the seq_id.

### Compressed Experience Blocks

Listing 40 rows verbatim would consume ~2000 tokens. Compressing into 4 summary blocks keeps the prompt under ~500 tokens, well within Haiku's sweet spot for fast, cheap responses.

### Logging All Responses

Every cycle is logged to `recordings/mrt_reflective_log.jsonl` — including `no_action`, skipped cycles (queue busy / suppressed), and failures. Each entry includes: timestamp, decision, reasoning, experience_window_size, queue_size_at_time, voice_text, and experience_id.

This is not just for debugging — it's a record of the robot's strategic reasoning over time, and a future dataset for fine-tuning.

### Graceful Degradation

- **No API key**: thread prints a warning and exits. Robot runs on rules only.
- **No `anthropic` SDK**: same behavior.
- **API failures**: logged, cycle skipped, robot continues on reactive rules.
- **Malformed LLM response**: falls back to `no_action`.

The robot never stops because of a missing LLM response.

### Thread Registration

In `run_data_collection()` in `recording_module.py`:

```python
from . import mrt_reflective_decisions as mrd

t_reflect = threading.Thread(
    target=mrd.reflective_decision_loop,
    args=(stop_event, stream_buffer),
    daemon=True
)
threads.append(t_reflect)
```

### API Key Management

The key is read from the `ANTHROPIC_API_KEY` environment variable. A `.env` file in the project root is loaded by `python-dotenv` in `run.py` at startup. The `.env` file is gitignored.

### Traceability

Every action row carries `source_module = 'mrt_reflective_decisions'`. Filtering `mrt_decisions_to_actions.csv` shows exactly what the LLM decided vs. the rule engine — side by side, timestamped, with reasoning in the JSONL log.

## 6. Three-Tier Decision Architecture

| Layer | Component | Fires | Latency | Intelligence |
|---|---|---|---|---|
| Reactive | `decision_engine.py` | Every ~3s (per chunk) | <10ms | Rules + keyword voice matching |
| Reflective | `mrt_reflective_decisions.py` | Every ~20s | ~1s | LLM (strategic + semantic voice) |

The reactive layer handles real-time reflexes: centering gaze on the cat, safety stops, and fast keyword-matched voice commands. The reflective layer handles strategic decisions: approaching a calm cat the rules haven't acted on, interpreting ambiguous voice commands, and recognizing behavioral patterns over a 60-second window.

Both layers write to the same `mrt_decisions_to_actions` schema and feed `BRAIN_COMMAND_QUEUE`. The motor cortex (`stream_motors`) arbitrates between manual input and brain commands without knowing which layer produced them.
